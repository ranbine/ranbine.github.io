② 流分离：出菜口 vs 后厨② Stream split: service window vs kitchen

点「运行」看一次调用的输出如何分流 —— stdout 只走最终结果（给程序），stderr 走叙述 + 工具日志（给人调试）。Hit Run to watch one call split — stdout carries only the final result (for programs), stderr carries narration + tool logs (for humans).

run-agent.sh reviewer "Review daily-report-2026-10-15.html" --contract json --quiet
stdout · 出菜口 · 给程序· service window · for programs
stderr · 后厨 · 给人调试· kitchen · for humans
实测发现：CLI 本就把 [tool] 日志写到 stderr；脚本再把 agent 的叙述剥到 stderr，并用 grep -o 'RESULT=.*' 行内抠取载荷（叙述常和 RESULT 拼同一行，故不能锚行首）。出菜口由此彻底干净。Measured: the CLI already routes [tool] logs to stderr; the script then peels the agent's narration to stderr and extracts the payload with grep -o 'RESULT=.*' (narration often shares the line with RESULT, so no ^ anchor). The service window ends up clean.
