机制一 · 分层分析 + 反偏见交接

对应真实实现：analyze-job.py（L1→L2→L3 分层）、triage.py（第一层分类） ·  对应能力：Orchestration 编排

① 理解大白话 + 生活类比

它要解决的问题

想象你是医院院长，每天几百个病人。如果每个病人一进门就直接上最贵的主任医师做全套检查（CT、核磁、专家会诊全上）——太贵、太慢，大部分人根本用不着。

在我的系统里，"病人"就是每天几百个测试失败。每个都直接调最贵的 AI 做最深分析，一样又贵又慢。

我的解法：像医院一样"分诊"

便宜的先上，贵的后上：
  • 第一层（护士台）：最便宜，快速看一眼。大部分失败一眼能归类——"老毛病，见过""环境抽风，重跑就行"。几百个里大多数在这层就解决，不惊动后面。
  • 第二层（门诊医生）：中等成本。拿不准的才到这里做初步判断——"我怀疑是 XX 原因"。
  • 第三层（专家会诊）：最贵。只有真正复杂、值得深挖的，才动用最深的分析验证。
核心思想一句话：别一上来就用最贵的手段，让便宜的先把简单情况筛掉。又快又省。

最妙的一招：防止"先入为主"

假设门诊医生写了个诊断"我觉得是肺炎"，转给专家。如果专家一开始就看到"肺炎"两个字，人的本能会不自觉往那个方向找证据、忽略其他可能——这叫"锚定效应"，医生和 AI 都会中招。

所以我做了个反常识的设计：交接时第一轮故意不把前面的结论告诉后面，让专家先独立看原始材料、形成自己的判断，之后才对照前面的结论。

大白话：我故意让第二个人"蒙着眼"先自己判断，免得被第一个人的答案带跑偏。两个独立判断凑一起，比一个人带着偏见从头做可靠得多。

② 介绍中文（给同事快速讲）

我处理测试失败用的是分层递进的思路：第一层做最便宜的快速分类，把"已知问题、环境问题、重跑即可"这类简单情况直接筛掉；拿不准的才进第二层生成假设；只有真正复杂的才进第三层做最深的分析验证。这样绝大多数失败在最便宜的一层就消化了，既快又省成本。

更关键的是我在层与层交接时加了一个反偏见设计：第一轮故意不把上一层的结论透露给下一层，让它先独立判断，之后再对照。这是从一个四角色对抗式 RCA 系统里学来的"信息屏障 / 反锚定"思想——避免下游被上游结论带偏。

③ 英语Spoken Script（当面讲给英语的人）

Plain version: "The way I handle test failures is like hospital triage — the cheap, fast checks go first and filter out the simple cases, and only the genuinely complex ones get the expensive deep analysis. It's fast and cost-efficient. And I added one anti-bias trick on purpose: when one layer hands off to the next, I deliberately don't show the next layer the previous conclusion first — I let it judge independently, so it doesn't get anchored to someone else's answer."
Technical version: "I built a layered L1-to-L3 analysis pipeline, cheapest-first. L1 does fast pattern-classification and resolves most failures — known issues, env flakes, rerun-needed. Only the uncertain ones escalate to L2 hypothesis generation, and only the genuinely hard ones reach L3 deep verification. The key design is a two-round anti-bias handoff: the first round withholds the upstream conclusion so the downstream forms an independent judgment — an information-barrier against anchoring, borrowed from a four-role adversarial RCA system I studied."

机制二 · Harness = Guarantee, Prompt = Hope

对应真实实现：结构化分类字段 + error-patterns.json 机械校验  ·  对应能力：Tool-calling / 可靠性

① 理解大白话 + 生活类比

先翻译这句话本身

  • prompt = hope（提示词 = 希望）：你跟 AI 说"请按这个格式输出"，这只是希望它照做。心情好就照做，不好就跑偏。
  • harness = guarantee（框架 = 保证）：你在外面套一层机械检查，不管 AI 输出啥都拿规则卡一遍。这才是保证。
一句话：别指望 AI 自觉，要用规矩兜底。

它要解决的问题

想象你请了个很聪明但偶尔不靠谱的实习生，让他填表："每个测试失败归成这五类之一。"大部分时候填得很好，但偶尔他会：自己发明第六种分类；一本正经填错、还看起来很有道理；编个根本不存在的原因、语气还特别肯定。

最可怕的不是他填错，而是他填错时也一脸自信——你要是全信，错误就悄悄流到下游酿成大祸。AI 就是这个实习生。

我的解法：出口装个"质检闸门"

我不信任实习生的善意，在他交表的出口装了道机械质检：
  1. 强制选项：分类只能是这五种，填别的直接打回——没法自创第六种。
  2. 对照检查表：维护一个"错误特征库"（error-patterns.json），他的结论拿这个库机械核对，对不上就报错。
  3. 错就大声报错（fail loudly）：质检不过当场停下、明确报错，绝不让可疑结果偷偷溜到下一步。

这跟 Memory Dream 是同一种思考

两个机制骨子里是一个思想：不相信"会自觉做对"，用外部的、机械的规矩兜底。
· Memory Dream：不信自己会手动整理 → 靠调度 + 硬上限兜底
· Harness：不信 AI 输出可靠 → 靠结构 + 机械校验兜底
这就是你的思考路径——面对不可靠的东西，不靠信任，靠制度。

② 介绍中文（给同事快速讲）

我不假设 AI 一定会按要求输出——那只是"希望"。所以我在它的输出口套了一层机械校验：分类字段强制只能从固定几种里选，填别的直接打回；结果还要跟一个错误特征库（error-patterns.json）机械核对，对不上就当场报错、绝不放行。因为 AI 最危险的不是出错，而是出错时还很自信，会把错误静默传到下游。我的原则是：靠规矩兜底，不靠 AI 自觉。

③ 英语Spoken Script（当面讲给英语的人）

Plain version: "I don't assume the AI will output what I asked — that's just hope. So I put a mechanical check on its output: the classification can only be one of a fixed set, anything else gets rejected, and the result is cross-checked against an error-pattern library — if it doesn't match, it fails loudly on the spot. Because the dangerous thing about AI isn't that it gets things wrong — it's that it's confident when it's wrong. My rule is: rely on structure, not on the model's goodwill."
The one-liner: "Harness is a guarantee; a prompt is only a hope. I validate structured output mechanically and fail loudly, rather than trusting the model to behave."
