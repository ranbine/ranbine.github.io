Progressive Authorization

What an agent may do is earned step by step from evidence — and the agent can't move that line itself.

①

Tier by reversibility and blast radius

Same rm: L1 in scratch, L3 in home, DENY elsewhere.

②

Observe before you block

Shadow mode logs only; switch to enforce on false-positive data, not gut feel.

③

Fail open on reads, closed on writes

Hooks sit on write tools only, so a broken guard never blocks diagnosis; in enforce any error blocks.

④

Separate mechanism, policy, identity

Shared code / policy template / personal config. Sharing means swapping only the last layer.

⑤

The governed can't edit the rules

Policy and gate are protected; approve, apply and mode run only in a real terminal.

⑧

Replay real logs before changing rules

The loop

  1. Tier
  2. Observe
  3. Replay
  4. Confirm
  5. Enforce
  6. Audit
  7. Propose

Automation may only tighten. Loosening = script proposes → reviewer judges → human applies (additions only). L3 never auto-downgrades.

Limits: the gate is still in shadow mode, with no enforce-phase data yet; string matching is a guardrail against mistakes, not a sandbox; ~33% of decisions sit in unreviewed L2.
