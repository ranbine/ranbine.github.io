01为什么做这个Why

会话失忆Session amnesia

每次新会话都要重新交代背景、偏好、上次做到哪。Every new session starts from zero: context, preferences, where we left off.

口头承诺不可靠Verbal promises don't stick

"下次我会注意"没有载体。规则必须写进文件并 commit。"I'll remember next time" has no storage. A rule only exists once it's in a committed file.

产出质量不稳定Uneven output quality

报告断链、漏翻译、占位符残留——需要机械检查 + 语义把关。Broken links, missing translations, leftover placeholders — needs mechanical checks plus semantic review.

03启动流程Startup flow

会话一开始，hook 先跑完所有确定性检查，只把一段摘要注入上下文；Agent 按固定优先级逐项处理，一次只问一个问题。On session start a hook runs every deterministic check and injects only a short digest; the agent acts on it in a fixed priority order, one question at a time.

触发词Trigger words→ 日报完整性Daily summary→ 认证检查Auth check→ Pending 队列Pending queue→ 周期回顾提醒Review reminders

05动作审核（Action gate）Action gate

Agent 的每次工具调用先经过一个 preToolUse hook：按策略文件以毫秒级判定风险等级并记录。分层依据是可逆性 × 影响范围，而不是动作类别——大部分动作只读，不该为它们付出 LLM 审核的代价。Every agent tool call first passes a preToolUse hook that classifies it against a policy file in milliseconds and logs the decision. Tiers follow reversibility × blast radius, not action type — most actions are read-only and shouldn't pay for an LLM review.

等级Tier典型动作Typical actions处理Handling
DENY改 gate / 策略 / agent 配置；删除允许范围外的路径Editing the gate, policy or agent config; deleting outside the allow-list始终阻止，不可审批Always blocked, not approvable
L3git push、破坏性 git、未识别为只读的 MCP 工具、给别人发邮件、无法解析的命令git push, destructive git, MCP tools not known read-only, mail to others, unparseable commands阻止，用户在真终端 kiro-gate approve <id> 放行一次Blocked; the user runs kiro-gate approve <id> in a real terminal for a one-time pass
L1自有路径内的写入、本地 commit、自有脚本、scratch 内删除Writes under own roots, local commits, own scripts, deletes inside scratch放行 + 记录Allowed + logged
L0只读：read / grep / git log、MCP 的 get_/search_/list_Read-only: read / grep / git log, MCP get_/search_/list_放行 + 记录Allowed + logged
L2其余未分类动作Everything else按配置放行 + 记录，留给周审计Allowed per config + logged, left to the weekly audit
shadow 观察Shadow (log only)→ 按新策略重放Replay on new policy→ enforceEnforce→ 周审计 gate-auditWeekly gate-audit→ 提案，用户确认Proposals, user confirms

审计只提案、从不改策略；L3 永不自动降级。kiro-cli 在 hook 崩溃或超时时会放行，所以 hook 自己 fail-closed：enforce 下任何内部错误都按阻止处理。The audit only proposes and never edits the policy; L3 is never auto-downgraded. kiro-cli lets a call through if the hook crashes or times out, so the hook fails closed itself: in enforce mode any internal error blocks.

定位：防止 agent 失误的护栏，不是安全沙箱。方法论见 progressive-authorization.md。Scope: a guard-rail against agent mistakes, not a sandbox. Methodology: progressive-authorization.md.

06纪律框架Discipline framework

同类错误出现两次就提炼成 pattern；pattern 毕业后进入三层纪律。每条规则都要挂来源和一次真实的翻车记录，没有实例的规则不收录。A mistake seen twice becomes a pattern; graduated patterns join a three-tier discipline. Every rule must cite its source and a real failure — no example, no rule.

Tier何时扫When示例Example
D-A · Analysis进入分析前Before analysis给了路径就直接读，禁止验证性搜索Given a path, read it — no verification searches
D-O · Output准备交付时Before output写前去重：UPDATE > MERGE > ADDDedup before write: UPDATE > MERGE > ADD

07可移植 & 去敏感Portable & leak-safe

同一套框架同时跑在私有实例和这个公开仓库里：框架文件逐字节一致，个人和领域内容全部放在被 git 忽略的 overlay 里。The same framework runs in a private install and in this public repo: framework files are byte-identical, and everything personal or domain-specific lives in gitignored overlays.

个人信息封装Personal overlay

身份、路径、时区、删除白名单放 config/local.env；额外标签、关键词放 local.json；私有 MCP 规则放 gate-policy.local.json；本地规则补充放 contexts/local/。Identity, paths, timezone, delete allow-lists in config/local.env; extra tags and keywords in local.json; private MCP rules in gate-policy.local.json; local rule additions under contexts/local/.

共享核心Shared core

shared-files.txt 列出必须逐字节一致的框架文件；sync-shared.sh 只拷清单内文件，受保护文件不同就整体中止；kiro-doctor 报告漂移。shared-files.txt lists framework files that must stay byte-identical; sync-shared.sh copies only listed files and aborts entirely if a protected file differs; kiro-doctor reports drift.

泄露防护Leak guard

pre-commit / pre-push 扫描绝对路径、邮箱、密钥；私有敏感词表放在仓库外，敏感词本身永不发布。pre-commit / pre-push scan for absolute paths, emails and keys; a private denylist lives outside the repo so the words themselves are never published.

08快速开始Quick start

需要 kiro-cli 和 Python 3。源码：github.com/ranbine/lab。Requires kiro-cli and Python 3. Source: github.com/ranbine/lab.

git clone https://github.com/ranbine/lab.git kiro && cd kiro
cp config/local.env.example config/local.env   # name / email / timezone
./install.sh --hooks                           # render agents, enable git hooks
./install.sh --install                         # copy into ~/.kiro/agents
python3 bin/gate-install.py install            # optional: action gate (starts in shadow)
kiro-cli chat --agent kiro-lab
